# Workflow

## Topology

- Initial topology intent: `generic-loop`.
- Reason: Planner, Coder pool, Synthesizer, Researcher, Evaluator, and Human Operator form a directed graph with cycles and parallel branches rather than a strict tree of local-close handoffs; profiler evidence is generated by a tool surface.
- Normal communication should use Houmao mail unless the generated execplan chooses a loop-local harness path for specific machine-readable state.
- Runtime target is launchable live Houmao operation, not offline-only documentation.

## Cycle

- Seed: current best candidate, active contest definition, allowed edit surface, benchmark protocol, run history, and known bottlenecks.
- First implementation scope: active Fused MoE only.
- Plan: Planner emits one or more optimization assignments.
- Implement: two CUDA Coders work independently in isolated workspaces, each completing one bounded attempt and producing candidate result mail.
- Profile: managed agents invoke the Profiler tool surface for targeted profiling requests or shortlisted candidates.
- Research: Researcher handles reference and idea requests when local progress stalls or a larger shift is needed, searching local references and network sources concurrently by default.
- Synthesize: Synthesizer compares results, selects or merges a promotion candidate, and summarizes lineage, conflicts, preserved ideas, and rationale.
- Evaluate: Gatekeeper runs correctness and benchmark gates, rejects invalid results, and sends promotion evidence to Planner only after `official-timing`.
- Iterate: Planner updates current-best state from accepted Evaluator evidence, then either starts the next cycle, asks for human redirection, or recommends that the Human Operator stop the loop.

## Candidate Lifecycle

- Proposed: Planner has issued an assignment with a hypothesis and evidence expectation.
- Implementing: a Coder owns one bounded attempt in an isolated workspace.
- Testing: the Coder or Evaluator runs correctness and timing checks.
- Profiling: the Profiler tool surface produces bottleneck evidence when needed.
- Submitted: the Coder sends result mail with changed files, local-check availability, metrics, failures, and next-step notes, then stops.
- Synthesized: the Synthesizer selects, merges, preserves, or rejects candidate ideas and submits a promotion candidate to Evaluator when appropriate.
- Accepted: the Evaluator confirms correctness and valid speedup evidence through `official-timing`, then Planner writes current-best state.
- Rejected: correctness, timeout, benchmark validity, anti-hacking, regression, or reproducibility failed.
- Waiting for GPU: no spare local GPU was available, so the assignment is recorded for later wakeup rather than failed.

## Message Families To Generate Later

- `planning-cycle-start`: operator or Synthesizer asks Planner to start a cycle.
- `optimization-assignment`: Planner sends one work item to a Coder.
- `coder-result`: Coder returns candidate evidence and changed-file summary.
- `profile-request`: Planner, Coder, Synthesizer, or Evaluator records a need for specific profiling evidence or invokes the generated Profiler tool surface.
- `profile-report`: generated profiler output records bottleneck attribution and metrics summary as an artifact or structured evidence item.
- `research-request`: Planner, Coder, or Synthesizer asks Researcher for references or implementation options, optionally overriding the default parallel local-and-network source scope.
- `research-summary`: Researcher returns source-backed ideas, source-scope notes, and risk notes.
- `synthesis-report`: Synthesizer returns selected or merged promotion candidate, lineage, merge notes, preserved ideas, and next Planner context.
- `evaluation-report`: Evaluator returns accepted or rejected status with evidence; accepted reports are sent to Planner for current-best state update.
- `operator-intervention`: Human Operator redirects, pauses, resumes, stops, invalidates, or changes constraints.

## Completion And Stop

- There is no automatic success completion condition.
- Accepted Evaluator evidence from `official-timing` lets Planner update the current best candidate and feeds the next planning cycle.
- Budget pressure, repeated failures, invalid-speedup concerns, and blocked search produce escalation reports or stop recommendations.
- Only an explicit Human Operator stop ends the loop.

## State To Track

- Current best candidate and active variant.
- Planner-owned current-best write records.
- Benchmark history and profiler artifacts.
- Assignment ids, candidate ids, workspace paths, and owning agents.
- Two Coder slots per normal planning cycle.
- Six isolated managed-agent workspace paths.
- One bounded attempt per Coder assignment.
- Waiting-for-GPU records and non-GPU retry counts.
- Failed directions, suspected causes, and directions to avoid repeating.
- Accepted speedups with correctness evidence and reproducibility notes.
- Rejected hacks or invalid candidates.
- Open hypotheses, blocked questions, and operator interventions.
